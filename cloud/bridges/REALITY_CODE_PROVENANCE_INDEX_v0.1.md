## 7. Recovery and reconciliation rule

If an original Reality-Code repository or package is recovered:

1. Do not overwrite or normalize it first.
2. Hash the recovered raw artifact/repository snapshot.
3. Record source account, repository/path, branch/ref, and retrieval date.
4. Compare the recovered contents against the project-history claim ledger and bridge summaries.
5. Preserve disagreements explicitly rather than silently choosing the newer narrative.
6. Mirror immutable source artifacts into a dedicated Reality-Code provenance area before deriving any new bridge claim.
7. Keep Reality-Code and LIFE-CODE experimental evidence distinct; connect them only through explicit bridge tests or formal correspondences.

## 8. Standing cross-reference rule

Before a new LIFE-CODE or Reality-Code proof/experiment step is promoted, review the latest available state of both projects and related experimental threads for:

- prior PASS/FAIL/null results that bear on the claim;
- already-frozen tests that would make a new test redundant;
- contradictory evidence;
- formal results that change the interpretation ceiling;
- data/provenance dependencies;
- candidate bridges that require a separately preregistered cross-project test.

The purpose is not to force all results into one theory. It is to prevent relevant evidence from being lost while preserving independent falsification paths.
